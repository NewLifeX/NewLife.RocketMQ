# 多语言本地化

> 基线：NewLife.Core 12 编译期词表｜运行时 31 种语言｜英文为源文与兜底

## 0. 运行环境约定

- 语言由 `Localization.Culture` 决定，未设置时取 `CultureInfo.CurrentUICulture`；日志统一走 `Localization.TranslateForLog`（可另设 `LogCulture`）。
- **NativeAOT 默认开启不变全球化**（`InvariantGlobalization=true`，可显著减小体积）。此模式下只有不变文化，无法解析 `zh-CN` 这类区域名，词表自动回退英文且不抛异常；需要非英文输出时，应用应关闭不变全球化以保留 ICU。
- AOT 冒烟（`AotSmoke`）内置「多语言·词表翻译与英文回退」用例：不变全球化下校验英文回退与格式化，保留 ICU 时校验译文与未支持语言回退。
- 老目标框架（net45 / net461 / netstandard2.0 / netstandard2.1）由源生成器补齐 `ModuleInitializer` 定义后在模块初始化时注册词表，能力与 net10.0 一致；net45 与 netstandard2.0 产物实测 zh-CN / zh-Hant / ja-JP / de-DE 命中译文，en-US 与未支持语言回退英文。
- 配置项 `[Description]` 已改为英文源文；NewLife.Core 写 ini/xml 配置注释时会做一次翻译（`LocalizeComment`，需 Core 版本包含该方法；当前 beta 尚未提供时注释按英文原样写出，词表已就绪，升级 Core 即生效）。
- 运行期依赖：`Locales` 目录缺失时源生成器不再产出 `L` 快捷入口，库无法编译，因此 **`Locales` 必须随源码提交**。

## 1. 覆盖范围

回退英文的前提是“消息进了词表”。本库所有**用户可见的运行期文本**都走词表：

| 类别 | 覆盖情况 |
|------|---------|
| 日志（`WriteLog` / `Log.*` / `XTrace`） | 全部，含带前缀日志（前缀在翻译之后拼接） |
| 协议解析异常（帧、varint、消息体长度、压缩） | 全部 |
| 公开 API 异常（参数校验、超时、gRPC 调用失败、管理接口限制） | 全部 |
| 配置项描述（`[Description]`） | 英文源文 + 译文（注释写出时翻译） |
| 编译期提示（`[Obsolete]`） | 英文，不走运行期词表（编译器直接输出属性值） |

日志前缀、方向标记（`=>` / `<=`）、主题/队列名等动态值不属于消息，**不参与词表查找**。

## 3. 词表文件

- `NewLife.RocketMQ/Locales`

- 文件名即 BCP 47 语言代码；英文是源文与兜底，**不需要** `en.yml`。
- 键为**英文原文**，必须与代码字符串逐字一致（含空格与标点）；占位符 `{0}` 与格式说明符 `{1:n0}` 必须与英文一致。
- 当前基准：`zh-Hans.yml` 共 **132 条**，其余 30 种语言与之逐条对齐。
- 词表由 NewLife.Core 包内的源生成器在编译期读取并生成本地化表，NativeAOT 下同样可用。**下游项目的表以字面量字典逐条嵌套生成（不做压缩）**，压缩表只存在于 Core 自身；因此语言数直接影响程序集体积。

### 3.1 体积与启动开销（实测）

net45 产物对比（同一份代码，仅 `Locales` 数量不同）：

| 语言数 | DLL 体积 | 首次触达耗时* |
|--------|---------|--------------|
| 1（zh-Hans） | 248,832 B | 66 / 94 / 114 ms |
| 31 | 716,800 B | 139 / 157 / 176 ms |

\* pwsh 冷进程内首次调用 `Localization.Get` 的耗时（含 Core 自身词表与 JIT），三次取样；应用常驻进程只需付一次。

- 30 种额外语言约占 **+468 KB**（字符载荷约 40 万字符，UTF-16 约 786 KB，元数据去重后实际增量约 470 KB）。
- 首次触达多付约 **+50~70 ms**，之后走静态表无额外开销。
- 若在意包体，可按 §3 精简语言文件（缺失语言自动回退英文，无需改代码）；当前按“对齐 NewLife.Core 31 种语言”维护。


## 4. 新增一条消息

1. 代码中写英文源文：`throw new XException("Session {0} is closed.", sessionId);`，日志直接写英文模板（`Logger.Format` 自动翻译）。
2. 在全部语言文件的同一位置补齐该键；遗漏只回退英文，不会编译失败。
3. 运行校验脚本确认键集合、占位符与格式说明符一致。

## 4.1 带前缀写日志

实例前缀（如 `[group]`、`[GrpcPushConsumer]`）**不得拼进消息模板**。`Logger.Format` 用整串查表，模板一旦带上动态前缀就永远匹配不到词条，只能回退英文。

正确写法是使用 NewLife.Core 的带前缀日志扩展，先翻译再拼接前缀：

```csharp
// 基类统一入口（MqBase.WriteLog / ClusterClient.WriteLog）
public void WriteLog(String format, params Object[] args) => Log?.InfoPrefixed($"[{this}]", format, args);

// 直接写日志时
Log.InfoPrefixed("[GrpcPushConsumer] ", "Started, Topic={0}, Group={1}, queues={2}", Topic, Group, count);
Log.ErrorPrefixed(Prefix, "Failed to pull messages: {0}", ex.Message);
Log.WritePrefixed(LogLevel.Warn, Prefix, "Heartbeat failed: {0}", ex.Message);
```

- 前缀常量集中在类内（如 `GrpcPushConsumer.Prefix`），不参与词表。
- `{0}` 占位符按翻译后的模板格式化，参数不受语言影响。
- 带前缀日志的回归测试见 `XUnitTestRocketMQ/Localization/LocalizationTests.cs`。

## 5. 校验

```powershell
pwsh -File check-locales.ps1 -LocaleDir NewLife.RocketMQ/Locales -SkipOrphan
```

脚本检查三类问题：

1. **键集合一致**：各语言键必须与基准 `zh-Hans.yml` 完全相同（新增/缺失都报错）。
2. **占位符一致**：`{0}`、`{1:n0}` 等占位符与格式说明符必须与英文源文一致。
3. **源码使用但词表缺失**：扫描 `L.T(...)`、`WriteLog`/`*Prefixed`/`Log.*`/`XTrace.*`/`throw new ...` 中的英文字面量，若不在基准词表内则报错（`-SkipUsage` 可跳过该项）。跳过短串、纯标识符、`=>` / `<=` 方向标记等非消息文本。

CI 的 localization job 会执行同一脚本，并额外运行 `LocalizationTests`（译文命中、未支持语言回退、带前缀日志、公开 API 异常、配置描述）。
